# ArdEVO paper: LaTeX build

This directory holds the venue-neutral LaTeX source for the ArdEVO paper, converted
from `../paper.md`.

## Files

| File | What it is |
|---|---|
| `main.tex` | The full paper: single-column `article`, 11pt, sections 1 to 11, Appendices A to D. |
| `references.bib` | 89 BibTeX entries, one per reference in the paper. Keys are `firstauthorYEAR` with `a`/`b` suffixes where the paper disambiguates (`elsken2019a`, `elsken2019b`). |
| `main.pdf` | The compiled output (40 pages). Regenerated by the build below. |

Figures live in `../figures/` and are pulled in via `\graphicspath{{../figures/}}`.
`fig1`-`fig4` are vector PDFs; `fig5a`-`fig5d` and `fig6` are PNGs.

## Build

The document compiles cleanly with a full TeX Live / MacTeX install.

```bash
# Preferred: latexmk runs pdflatex -> bibtex -> pdflatex -> pdflatex as needed.
latexmk -pdf main.tex

# One-shot alternative:
tectonic main.tex

# Manual sequence (equivalent):
pdflatex main.tex
bibtex   main
pdflatex main.tex
pdflatex main.tex

# Clean auxiliary files:
latexmk -C
```

### Compilation status

Compiled with `latexmk -pdf` against TeX Live 2026 (`pdflatex` + `bibtex`).
Result: **40 pages, clean** (no undefined references or citations, no overfull/underfull
boxes above threshold, no float-too-large warnings, no LaTeX warnings). All 89
bibliography entries resolve and the `elsken2019a`/`elsken2019b` author-year
disambiguation renders as `(2019a)` / `(2019b)`.

## Packages used

`fontenc` (T1) + `lmodern`, `underscore`, `geometry`, `microtype`, `amsmath`,
`amssymb`, `booktabs`, `tabularx`, `array`, `graphicx`, `caption`, `subcaption`,
`enumitem`, `natbib` (`authoryear,round`, `plainnat` style), and `hyperref` (loaded
last). All are in a standard full TeX distribution.

Two choices worth knowing:

- **`underscore`** lets a bare `_` typeset safely in text and inside `\texttt{}`, so
  the many code identifiers in this paper (`run_summary.json`, `max_sample_accuracy`,
  `refine_steps`, ...) render without per-underscore escaping. `\emergencystretch` is
  set so the occasional long unbreakable `\texttt` code string does not overflow the
  margin.
- **`\graphicspath`** points at `../figures/`, so run the build from this directory.

## Changing venue

The source is deliberately venue-neutral. To target a specific venue:

1. **Swap the class / style.** Replace `\documentclass[11pt]{article}` with the venue
   class (e.g. `\documentclass{article}\usepackage{neurips_2026}`, or an ACM/IEEE
   class). Most venue styles bring their own `geometry`, title block, and often their
   own bibliography style, so remove the conflicting pieces from the preamble:
   - drop the `\usepackage[margin=1in]{geometry}` line if the class sets margins;
   - if the venue mandates a bibliography style, replace `\bibliographystyle{plainnat}`
     (some venues ship a `natbib`-compatible `.bst`, e.g. `\bibliographystyle{plainnat}`
     stays fine; ACM/IEEE classes replace `natbib` entirely, in which case convert the
     `\citep`/`\citet` calls to that class's citation macros).
2. **Title / author block.** Venue classes usually redefine `\author`, `\affiliation`,
   and the abstract environment. The draft-status line is currently a `\thanks`
   footnote on the author; move it to the class's notes mechanism if needed.
3. **Two-column layout.** If the venue is two-column, the wide tables (the 18-rung
   table, the operator registries, the hyperparameters table, reproducibility) will not
   fit a single column. Wrap each in `table*` (full-width float) or shrink further with
   `\resizebox`. The `tabularx` `L` columns already wrap text, so `table*` is usually
   enough.

## Page budget note

This is a **full-length working draft at 40 pages** (body through Section 11, then
Appendices A to D, then references). That is far over the 8 to 10 page main-text limit
of most ML venues. Before submission the body must be condensed to the venue's page
budget, with the operator registries, the full hyperparameter table, reproducibility,
and compute/impact moved to a supplementary appendix (most venues allow unlimited
appendix pages after the references). Related Work (Section 2) and the two-spirals case
study (Section 7.3) are the two densest sections and the natural first targets for
tightening.

## Prose convention

The source and this conversion contain **no em dash** characters and no `---` em-dash
ligatures in prose (the `---` sequences in `main.tex` appear only inside `%` comments,
and `--` appears only as en dashes in `references.bib` page ranges). Preserve this when
editing.
